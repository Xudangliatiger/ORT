## Overview

ORT weights token cross-entropy by position during randomized-order training:

```text
w(t) = alpha + (beta - alpha) × t / (T - 1)
```

The training order gradually transitions to raster order. This repository contains
the ORT generator, its loss, matching tokenizer code, a portable trainer with
full-state resume, image sampling, and the original AliTok and RAR generators.

| Method | Training order | Image tokens | Vocabulary | Example recipe |
|---|---|---:|---:|---|
| **ORT-E / AliTok-XL** | Random → raster, early-biased loss | 273 | 4096 | [400 epochs](configs/ort_e_alitok_xl_400.yaml) |
| **ORT-L / AliTok-XL** | Random → raster, late-biased loss | 273 | 4096 | [300 epochs](configs/ort_alitok_xl.yaml) |
| Original AliTok-XL | Raster, uniform loss | 273 | 4096 | [400 epochs](configs/alitok_xl_original_400.yaml) |
| Original RAR-XL | Random → raster, uniform loss | 256 | 1024 | [400 epochs](configs/rar_xl_original_400.yaml) |

Original baselines retain upstream generator source and checkpoint key layouts.
See [provenance and adaptation details](docs/BASELINES.md); the shared trainer is
not a byte-identical replacement for each complete upstream training system.

## Installation

```bash
git clone https://github.com/Xudangliatiger/ORT.git
cd ORT
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m pytest -q
```

Choose a PyTorch build appropriate for your CUDA environment. On HPC systems,
an isolated environment can reuse the site's PyTorch module. No private paths,
cluster launch scripts, credentials or training datasets are bundled.

## Quick start

Download the verified generator and recipe:

```bash
python scripts/download_models.py --model ort-e-alitok-xl-400 --output weights
```

Obtain the matching AliTok tokenizer from [Models & downloads](docs/MODELS.md).
Then generate one image with the validated ORT-E recipe:

```bash
python scripts/check_inference.py \
  --config configs/ort_e_alitok_xl_400.yaml \
  --checkpoint weights/ort-e-alitok-xl-400.bin \
  --tokenizer-weights weights/AliTok.pth \
  --seed 2 --output outputs/example
```

The output includes `sample.png` and the generated tokens. Add `--backward-check`
to run one synthetic optimizer update after inference. This is a compatibility
check, not a training-quality experiment.

For token-only inference, including original baselines:

```bash
python sample_tokens.py \
  --config configs/rar_xl_original_400.yaml \
  --checkpoint weights/rar_xl.bin \
  --seed 2 --labels 1 7 --output outputs/rar_tokens.npz
```

## Training

Provide a Hugging Face dataset saved with `save_to_disk`, containing `label` and
`tokens` columns. Each token record can contain one sequence or multiple crop
sequences. Preserve tokenizer IDs, class labels, crop variants and sample count.

```bash
accelerate launch --num_processes 32 train.py \
  --config configs/ort_e_alitok_xl_400.yaml \
  --dataset /path/to/alitok_tokens --output outputs/ort_e_seed42
```

| Setting | ORT-E XL 400 | ORT-L XL 300 |
|---|---:|---:|
| Optimizer updates | 250,000 | 187,500 |
| Warmup updates | 62,500 | 62,500 |
| Random-order annealing | 125,000–187,500 | 62,500–125,000 |
| Global batch | 2048 | 2048 |
| Random-phase (alpha, beta) | (1, 0) | (0.75, 1.25) |

Maintain `world size × per-GPU batch × accumulation = 2048`. Multi-host jobs also
need Accelerate machine count, rank and rendezvous settings. Epoch labels use the
source's nominal 625 updates per epoch. A 400-epoch run stopped at epoch 300 is
not a complete 300-epoch cosine recipe.

### Short runs and resume

`--stop-after 10` stops after ten optimizer updates without changing the horizon.
Resume with the same config, dataset and world size:

```bash
accelerate launch --num_processes 32 train.py \
  --config configs/ort_e_alitok_xl_400.yaml \
  --dataset /path/to/alitok_tokens --output outputs/ort_e_seed42 \
  --resume outputs/ort_e_seed42/checkpoint-0000010
```

Training seeds are stored in configs; sampling seeds are separate CLI arguments.
Use independent training seeds for repeats, and fixed sampling settings for paired
checkpoint comparisons. Worker-level crop RNG is not guaranteed identical on resume.

## Evaluation

Generate a balanced 50k-image archive with 50 samples per ImageNet class:

```bash
python sample_images.py \
  --config configs/ort_e_alitok_xl_400.yaml \
  --checkpoint weights/ort-e-alitok-xl-400.bin \
  --tokenizer-weights weights/AliTok.pth \
  --seed 2 --count 50000 --output outputs/samples.npz

python /path/to/guided-diffusion/evaluations/evaluator.py \
  /path/to/VIRTUAL_imagenet256_labeled.npz outputs/samples.npz
```

Use the [official ADM evaluator](https://github.com/openai/guided-diffusion/tree/main/evaluations)
and [ImageNet-256 reference batch](https://openaipublic.blob.core.windows.net/diffusion/jul-2021/ref_batches/imagenet/256/VIRTUAL_imagenet256_labeled.npz).
Archives use uint8 NHWC `arr_0`. Allow about 20 GB free disk for temporary and final
arrays. Record checkpoint hashes, sampling seed, batch size, CFG, evaluator version
and complete metric output. Full 50k evaluation is not yet validated here.
